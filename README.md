# Бриф · Этап 1 · Единый инбокс

Одностраничный бриф для клиента. Клиент открывает ссылку, отвечает на 19 вопросов,
нажимает «Отправить» — ответы коммитятся в этот же репозиторий в папку `answers/`.
Дальше `git pull` — и они лежат у вас на диске.

Никакой базы данных, никаких сторонних сервисов и регистрации для клиента.
Страница статическая, всю работу делает одна serverless-функция на Vercel.

## Видимость репозитория

Репозиторий публичный — это осознанное решение. Всё, что клиент напишет в брифе,
попадёт в `answers/` и будет доступно любому по ссылке, включая поисковики.

Если понадобится закрыть: Settings → General → Danger Zone → Change repository
visibility → Private. Vercel работает с приватными репозиториями на бесплатном тарифе,
менять в коде ничего не нужно.

## Структура

```
index.html        страница брифа
lib/questions.js  все вопросы и форматирование текста — один источник правды
api/submit.js     serverless-функция: проверяет ответы и коммитит их в репозиторий
answers/          сюда падают заполненные брифы (появится после первой отправки)
```

Вопросы правятся только в `lib/questions.js` — страница и функция берут их оттуда.

## Оформление

Страница сделана в стиле seoagency.ge, чтобы клиент узнавал агентство. Токены лежат
в `:root` внутри `index.html`, менять цвета и шрифты нужно там:

| | значение |
|---|---|
| фон | `#050505`, панели `#0A0A0A` |
| акцент | `#10B981`, светлый `#34D399`, градиент `135deg` между ними |
| текст | белый с прозрачностью: `.92` основной, `.62` вторичный, `.40` подписи |
| границы | белый `.10`, у карточек `.05` |
| шрифты | Manrope (400–800) и JetBrains Mono для цифр и подписей |
| радиусы | карточки 24px, кнопки и чипы — полные скругления |

Скачиваемая копия ответов (функция `buildDocument` в `index.html`) намеренно светлая —
она печатается в PDF. Акцент и шрифты в ней те же.

## Как запустить

### 1. Токен GitHub

1. [github.com/settings/personal-access-tokens/new](https://github.com/settings/personal-access-tokens/new) —
   fine-grained токен.
2. Repository access → Only select repositories → выберите этот репозиторий.
3. Permissions → Repository permissions → **Contents: Read and write**. Больше ничего не нужно.
4. Срок действия поставьте осознанно: когда он истечёт, отправка молча перестанет работать.
5. Скопируйте токен — он показывается один раз.

### 2. Vercel

1. Подключите репозиторий на [vercel.com](https://vercel.com) → New Project.
2. Framework Preset: **Other**. Build Command и Output Directory оставьте пустыми.
3. Settings → Environment Variables → добавьте на все окружения:

   | Переменная | Значение | Обязательна |
   |---|---|---|
   | `GITHUB_TOKEN` | токен из шага 1 | да |
   | `GITHUB_OWNER` | `akourmaz` | нет, определяется само |
   | `GITHUB_REPO` | `brief` | нет, определяется само |
   | `GITHUB_BRANCH` | ветка для ответов, по умолчанию `main` | нет |
   | `ANSWERS_DIR` | папка для ответов, по умолчанию `answers` | нет |

4. Deploy, затем проверьте: заполните пару вопросов и нажмите «Отправить».

Если переменные добавлены после первого деплоя — нажмите Redeploy, иначе функция их не увидит.

## Как забрать ответы

```bash
git pull
```

Каждый бриф — один файл `answers/2026-09-18-15-30.md`, имя по дате и времени отправки.
Внутри читаемый текст (удобно смотреть прямо на GitHub) и тот же набор ответов
в блоке `json` — для обработки.

Коммиты помечены `[skip ci]`, поэтому присланный бриф не запускает пересборку на Vercel.

## Что происходит, если отправка не прошла

Ответы не теряются ни в каком случае:

- всё, что клиент ввёл, лежит в `localStorage` его браузера и переживает перезагрузку;
- при ошибке страница показывает предупреждение и сразу открывает окно с текстом
  ответов, плюс работает кнопка «Скачать файлом»;
- если GitHub не ответил, функция пишет полный payload в логи Vercel — оттуда его можно достать.

## Локальная проверка (необязательно)

```bash
npx vercel dev
```

Без `vercel dev` страница откроется и так (`npx serve .`), но кнопка «Отправить» вернёт
ошибку — функции `/api/submit` не существует. Это нормально: сработает запасной путь
с файлом и текстом.

## Ограничения

- Ответы привязаны к браузеру. Начал на телефоне — продолжай на телефоне.
- Эндпоинт `/api/submit` открыт всему интернету. Он принимает только известные вопросы
  и режет длину полей, но от спама не защищён — в репозиторий может прилететь мусорный файл.
  Ссылку на бриф стоит давать адресно, а не публиковать.
- Страница закрыта от индексации через `noindex`.
