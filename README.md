# Бриф · Этап 1 · Единый инбокс

Одностраничный бриф для клиента. Клиент открывает ссылку, отвечает на 19 вопросов,
нажимает «Отправить» — ответы приходят в Telegram: читаемым текстом и файлом `.json`
для дальнейшей обработки.

Никакой базы данных и регистрации: страница статическая, отправкой занимается одна
serverless-функция на Vercel. Токен бота живёт в переменных окружения и в браузер не попадает.

## Структура

```
index.html        страница брифа
lib/questions.js  все вопросы и форматирование текста — один источник правды
api/submit.js     serverless-функция: проверяет ответы и шлёт их в Telegram
```

Вопросы правятся только в `lib/questions.js` — страница и функция берут их оттуда.

## Как запустить

### 1. Бот в Telegram

1. Напишите [@BotFather](https://t.me/BotFather) → `/newbot` → придумайте имя и username.
2. Он пришлёт токен вида `1234567890:AA...` — это `TELEGRAM_BOT_TOKEN`.
3. Напишите своему новому боту любое сообщение (без этого он не сможет писать вам первым).
4. Узнайте свой chat id: откройте
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найдите `"chat":{"id":123456789`.
   Это `TELEGRAM_CHAT_ID`.

Хотите, чтобы бриф падал в общий чат команды — добавьте бота в группу, напишите там
сообщение и возьмите id группы из того же `getUpdates` (он будет отрицательным).

### 2. Vercel

1. Подключите этот репозиторий на [vercel.com](https://vercel.com) → New Project.
2. Framework Preset: **Other**. Build Command и Output Directory оставьте пустыми.
3. Settings → Environment Variables, добавьте на все окружения:
   - `TELEGRAM_BOT_TOKEN`
   - `TELEGRAM_CHAT_ID`
4. Deploy. После деплоя проверьте: заполните пару вопросов и нажмите «Отправить».

Если переменные добавлены после первого деплоя — нажмите Redeploy, иначе функция их не увидит.

### 3. Локальная проверка (необязательно)

```bash
npx vercel dev
```

Без `vercel dev` страница тоже откроется (`npx serve .`), но кнопка «Отправить» вернёт ошибку —
функции `/api/submit` не существует. Это нормально: сработает запасной путь с файлом и текстом.

## Что происходит, если отправка не прошла

Ответы не теряются ни в каком случае:

- всё, что клиент ввёл, лежит в `localStorage` его браузера и переживает перезагрузку;
- при ошибке отправки страница показывает предупреждение и сразу открывает окно с текстом
  ответов, плюс работает кнопка «Скачать файлом»;
- если Telegram не ответил, функция пишет полный payload в логи Vercel — оттуда его можно достать.

## Важные ограничения

- Ответы привязаны к браузеру. Начал на телефоне — продолжай на телефоне.
- Эндпоинт `/api/submit` открыт всему интернету. Он принимает только известные вопросы
  и режет длину полей, но от спама не защищён. Ссылку на бриф стоит давать адресно,
  а не публиковать.
- Страница закрыта от индексации через `noindex`.
